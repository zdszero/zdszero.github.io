# Wiki repo conventions

How this Wiki repo turns `sources/*.md` into the published site, and the rules an enhanced doc must obey so it builds correctly.

## Layout

- `sources/<topic>.md` — the authored source. This is what you edit.
- `docs/<topic>.html` — the published page, produced by an **external pandoc-based build pipeline**. Do **not** hand-edit it; it is regenerated.
- `docs/WikiImage/<name>.svg` — hand-authored figures referenced by the md.
- `sources/index.md` + `docs/.wiki_sidebar.html` — the page registries (table of contents / left sidebar).

## Markdown conventions

- **Title line:** the file's first line is `% Title` (pandoc title block), not `# Title`. Everything after is body.
- **Section headers:** use `###` (h3) for the main sections. The build's on-page TOC lists **only `###` headers** — if you want a section to appear in the TOC, it must be `###`. Deeper headers (`####`) render but don't show in the TOC; use them for sub-points.
- **Images:** reference as `![alt](../docs/WikiImage/<name>.svg)` from the md. The build rewrites `../docs/WikiImage/` → `./WikiImage/` in the generated HTML, so the `../` prefix is correct in source even though it looks off. Name files `<topic>_<aspect>.svg`.
- **Language:** these docs are Chinese; keep terminology consistent with sibling pages.

## Registering a new page

If the topic is new (not just an edit of an existing page), it must be listed in **both**:
1. `sources/index.md` — add a line alongside the sibling entries.
2. `docs/.wiki_sidebar.html` — add a sidebar entry alongside the siblings.

For an edit to an existing page, confirm it's already in both (it usually is) — don't duplicate.

## Build / regeneration

- The HTML is generated by a custom external pandoc pipeline (bare `<ul>` TOC with `id="toc-"` prefixes, uniform body indentation, sidebar fetched at runtime). It is **not reliably reproducible by hand** — never hand-write or hand-patch `docs/*.html`.
- After editing the md and SVGs, **tell the user to rebuild**; do not try to produce the HTML yourself.
- Validate your SVGs are well-formed XML before finishing: `python3 -c "import xml.dom.minidom; xml.dom.minidom.parse('docs/WikiImage/<f>.svg')"`.

## Verify before reporting done

- Every `![...](../docs/WikiImage/x.svg)` in the md resolves to a file that exists.
- No placeholder markers left in the md or SVGs.
- The page is registered in `sources/index.md` and `docs/.wiki_sidebar.html` (new pages only).
